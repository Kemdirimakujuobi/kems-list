# Kem's List — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A free, zero-maintenance, Tempo-style curated list of African writing, with a keyboard desk and RSS.

**Architecture:** Static site; `data/*.json` in a public GitHub repo is the database. A Node discovery
script (GitHub Actions cron) fills `queue.json` from writers' feeds; a static `/desk` page edits the
curator-owned JSON through the GitHub Contents API; a Node build script renders HTML + `feed.xml` to
GitHub Pages on every relevant push.

**Tech Stack:** Node 22 (ESM), `fast-xml-parser` (only dependency), `node:test`, plain HTML/CSS/JS, GitHub Actions + Pages.

**Spec:** `docs/superpowers/specs/2026-10-15-kems-list-design.md`

## Global Constraints

- One runtime dependency: `fast-xml-parser`. No frameworks, no bundler, no web fonts, no tracking.
- File ownership: desk → `writers.json`, `inbox.json`, `pieces.json`, `skipped.json`; job → `queue.json`, `status.json`.
- `id` = first 12 hex of `sha1(canonicalUrl)`; canonical = lower-case host, no `utm_*`/`ref`/`source` params, no hash, no trailing slash.
- Excerpt ≤ 280 chars, sentence/word boundary, "…". Read time = words / 230 (rounded, min 1).
- New writer seeds 3 most recent items. Drop audio/video enclosures and < 300-word items (when length known). Paid Substack → `paywalled: true`.
- Fetch: 15 s timeout, 2 MB cap, UA `KemsList/1.0 (+https://kemdirimakujuobi.github.io/kems-list/)`.
- Build fails on any schema violation. Site base path `/kems-list/` from one config value.
- Shared modules in `lib/` must run in both Node and the browser (no Node imports).

## Review Focus

1. Feed items with HTML entities / CDATA / missing dates → clean titles, sane dates (Task 2).
2. Titles, notes and excerpts with `<`, `&`, quotes → escaped everywhere in HTML and RSS (Task 5).
3. Desk save conflict (file changed since load) → re-fetch, re-apply, no lost action (Task 4).
4. One writer's feed 404s or returns garbage → others still processed, status recorded (Task 3).
5. A piece already published or skipped reappears in a feed → never re-queued (Task 3).
